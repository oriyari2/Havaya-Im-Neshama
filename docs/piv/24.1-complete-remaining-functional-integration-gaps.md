# Task 24.1 PIV: Complete Remaining Functional Integration Gaps

## Evidence

The product-completeness audit compared every FastAPI route with Desktop
services, Presenters, Views, navigation, role authorization, CQRS/Event Sourcing,
cache behavior, tests, and current documentation. No missing business module or
unreachable approved workflow was found.

One obsolete flow remained: Customer-owned profile still rendered all contact
rows even though the approved model has one contact person. The profile now
uses the same Customer details as Manager view—contact name and phone only.
All independent Desktop contact methods were removed. Customer create/update
now persists the Customer and its single contact person in one backend
transaction, preventing a partially created Customer when contact persistence
fails.

Backend compatibility tables and historical inactive contacts remain. Current
reads select one primary/current active contact. A second active creation or
reactivation is rejected with HTTP 409 before a write, aligning API behavior
with the one-contact product model without deleting history.

Booking field parity was verified. Customer-create already includes notes;
notes persist in `BookingCreated`, projection, detail, and authorized Customer/
Manager reads. Instructor-safe responses continue to omit commercial/private
fields.
