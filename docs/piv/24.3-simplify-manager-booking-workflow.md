# Task 24.3 PIV: Simplify Manager Booking Workflow

The audit selected existing `NEW` as pending and proved the flow can be composed
in Desktop Presenters over existing APIs. Manager creation may select an
Instructor, but `POST /bookings` remains unchanged and emits only
`BookingCreated`; creation then delegates to the existing assignment Presenter
and command.

For pending requests, Booking Details offers one action that selects an
Instructor, assigns using the current aggregate version, then confirms using the
assignment response version. Status and assignment remain separate events and
projections. If a pending Booking is already assigned, the action confirms with
the loaded projection version and does not assign again. Customers remain
unassigned; Instructors cannot create/self-assign.

Tests cover optional selection without payload leakage, post-create delegation,
assignment reuse, assign/confirm version handoff, role visibility, and unchanged
Event Sourcing/query behavior. Task 25 was not started.
